# Settings and email verification

- Privacy & security has the email two-step toggle directly beside its label and shows blocked players with unblock controls. The extra toggle screen and Settings back button were removed.
- Each toggle change requires a new password confirmation, even after a recent login, then a code delivered to the verified account email. The setting changes only after the code is verified. Google-only accounts can reconfirm through their provider instead of entering a password they never created. Password, direct Google and Supabase sign-in all pass through the same second-step completion function.
- Codes expire after five minutes, are single-use, and are stored as keyed digests. Requests and attempts are limited. Changing the setting invalidates older account sessions. The existing account email provider must work before users enroll; no production delivery was tested in this change.
- Private-chat and group/community notification switches are independent. Preferences are checked before creating notifications and again before queued push delivery. Messages remain available when alerts are muted. This does not introduce alerts for every community post.
- Languages use searchable native-name/English-name rows. Only the existing English, Spanish, French and Portuguese catalogs are selectable. Additional screenshot languages remain unavailable until translations are ready, as requested by the owner. Untranslated copy falls back to English; user content is never sent to a translation service. Long legal text still needs editorial translation review.
- Migration `20261029_settings_security` adds security challenge storage and notification preference columns without deleting existing records. Two-step verification defaults to off. Existing chat preferences remain respected.
- Mobile signup spacing, shared tournament footer and collapsible policy contents were refined. Winner-only pilot rules, payouts and tournament records were not changed.
- Signup now matches the login card: Google at the top, username/email/password fields all visible, then the age field and agreement at the bottom. Google uses the same age/consent inputs without requiring the email/password fields. Server age/consent validation remains unchanged. Shared card/panel text-to-action spacing is more consistent.
- Google signup finishes its same-origin POST on a short internal handoff page before normal navigation to the OAuth endpoint. This prevents the browser's existing `form-action` policy from blocking the external redirect. The policy, CSRF checks, age/consent validation, OAuth state and PKCE checks are unchanged. The handoff requires a current validated signup declaration and is not cached. A browser fixture reproduced the original stall with valid synthetic inputs; after the fix it reached Google using a deliberately invalid test client. No real account was created.
- The privacy notice has an X that dismisses it for the tab without granting analytics consent. Cookie choices can reopen it. Inline policy/support links are underlined with theme-appropriate emerald/cyan colors.

Local verification uses synthetic accounts and an isolated PostgreSQL database, with email delivery mocked. Never copy production codes, passwords or keys into tests.
