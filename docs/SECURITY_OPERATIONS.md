# GameArena security operations

Prepared 19 October 2026. Code changes do not switch on security settings in external accounts. No production penetration test or account takeover was performed. An open Cloudflare HTTP/HTTPS port alone is not evidence of compromise.

## Before deploying

1. Privately enable MFA on your email first, then [Cloudflare](https://developers.cloudflare.com/fundamentals/user-profiles/2fa/), [Render](https://render.com/docs/login-settings), [GitHub](https://docs.github.com/en/authentication/securing-your-account-with-two-factor-authentication-2fa/about-two-factor-authentication), [Supabase](https://supabase.com/docs/guides/platform/multi-factor-authentication) and [Paystack](https://support.paystack.com/en/articles/2132098). Prefer passkeys or an authenticator where supported. Store recovery codes separately. Never send setup keys, QR codes, recovery codes or API credentials through chat.
2. The redacted history scan flagged three possible credentials in `.env.local-postgres-backup` in commit `21224bb50d540766a2bc06ea27994c80e494f832`. Treat genuine values as exposed and revoke/replace them privately with their issuing providers. The detector labels are not proof that every match is a real or active credential. Removing or ignoring a file does not revoke a key or erase old clones. Do not paste the values into an issue. Coordinate any later history rewrite with all contributors; it was not done automatically.
3. Apply migrations through `python scripts/migrate.py` during releases. Existing factor tables remain private for compatibility; application authenticator enrollment and challenges are retired.

## Account protection

As requested by the owner on 21 October 2026, GameArena no longer requires authenticator codes for players or administrators. Old enrollment/challenge URLs redirect to account security. Existing factors are not read or used to gate HTTP, socket connections or password confirmation. `SECURITY_ENFORCE_ADMIN_MFA` is ignored. Normal sign-in, session revocation, audit logging, origin protection and fresh primary sign-in for sensitive financial/admin actions remain in place. External-provider MFA settings are unchanged.

For sensitive actions, a stale session must confirm its password or sign in again with its usual provider. The action is not replayed automatically. Owner session revocation remains available through `scripts/security_admin.py` with explicit account confirmation and privately configured database access.

## Optional origin protection: configure both sides first

Origin protection remains off until privately configured. To block bypass through the Render hostname:

1. Generate a private random secret of at least 32 characters yourself. In Cloudflare, configure an origin request-header rule to **overwrite** `X-GameArena-Origin` with that secret for the GameArena hostname. Do not put it in JavaScript, a public repository or a screenshot. See [Cloudflare origin protection](https://developers.cloudflare.com/fundamentals/security/protect-your-origin-server/). Confirm your plan supports the required rule.
2. Set the same secret as `ORIGIN_SHARED_SECRET` in Render; only then set `ORIGIN_PROTECTION_ENABLED=true`. The web app fails startup if protection is enabled without a sufficiently long secret. For rollback during a configuration outage, set the enable flag false, fix the rule privately, and retest before reenabling.
3. Confirm the canonical site, login, uploads, Socket.IO polling/WebSocket upgrades and signed Paystack webhooks work through Cloudflare. Configure Paystack callbacks/webhooks to use the canonical protected hostname. Signature verification remains required; the origin secret does not replace it. Requests directly to Render should return 403. Never test a real payout merely to check networking.
4. Exact `GET`/`HEAD /health` remain public for Render checks. Other methods and paths require the secret. [Render health checks](https://render.com/docs/health-checks) use the custom-domain Host when available. Host validation allows the configured public hostname, `RENDER_EXTERNAL_HOSTNAME`, loopback and explicit `GAMEARENA_ALLOWED_HOSTS`. Do not add wildcard domains. Include any legitimate additional hostname deliberately.

The wrapper also covers Engine.IO handshakes before Flask routing. Cloudflare client-IP headers are trusted only when private origin validation is enabled; otherwise rate limits use the actual peer address. This avoids arbitrary clients selecting their rate-limit identity, but shared proxy addresses can produce stricter limits until origin validation is configured. This is an application-level defense for a managed host, not a claim that the origin is unreachable at the network layer.

## Audit, alerts and incident response

`/admin/security-events` shows paginated administrator-only records: actor ID, action, endpoint name, method, status, request ID and time. Passwords, factor codes, bank details, request bodies and URL query strings are not stored in these new audit events. Login/logout, factor changes, denied access and financial/admin submissions are recorded. A record of a submission is not proof that a payment settled; use the wallet ledger/provider reconciliation for that.

Audit inserts use a separate transaction; storage failure emits `security_alert kind=audit_storage_failure`. Records live in the same database, so a database administrator can alter them. Configure a restricted external log archive when choosing storage, set a retention period appropriate to privacy/accounting needs, and monitor storage growth. No automatic deletion or immutable external archive is configured in this release.

Structured `security_alert` warnings flag request-volume, repeated authentication/MFA failures, payment failures, origin rejections and server errors. Counters are bounded per worker per minute; this is monitoring, not a complete IDS or DDoS defense. Set optional `SECURITY_ALERT_EMAIL` privately to one owner-controlled address to deliver threshold notifications through the existing email service, at most once per five minutes per worker. Delivery requires working email configuration and is not guaranteed if a process/host is down. Without that setting, alerts remain in hosting logs. Connect an external uptime/log alert service separately; none was purchased or enabled here.

For a suspected incident: preserve redacted timestamps/request IDs and relevant logs; set `WITHDRAWALS_ENABLED=false` to pause new withdrawals before any debit/provider call; revoke affected sessions; investigate provider transaction records and existing pending payouts before retrying anything; rotate genuinely exposed keys privately; recover only after understanding the incident. The pause does not cancel a transfer already submitted to Paystack. Do not publish player data or exploit details. Use scoped, non-destructive tests with accounts you control; production payment manipulation and load attacks were not part of these checks.

## Encrypted local backups

`scripts/backup_database.py` streams a PostgreSQL custom-format dump into AES-256-GCM encrypted `.gabk` files. It never loads `.env`, does not overwrite existing backups, and does not put passwords or keys in command arguments. Backup keys and database URLs are read from private environment variables. Verification authenticates the entire file before invoking PostgreSQL tools; verification/restore use an OS temporary decrypted archive which is closed afterward. Keep the computer and its disk protected too.

Owner setup, performed privately:

1. Install PostgreSQL client tools compatible with your database and Python dependencies from the project. Generate a backup key yourself with `python scripts/backup_database.py generate-key`; keep a separate secure copy outside this computer. This key is separate from MFA encryption and VAPID keys. Losing it makes the backup unrecoverable.
2. Run `powershell -NoProfile -File scripts/setup_private_backup.ps1 -Python PATH_TO_YOUR_PYTHON`. Add `-PostgresBin "C:\Program Files\PostgreSQL\17\bin"` if client binaries are not on PATH. The script prompts for the database URL and backup key without displaying them and stores them using Windows DPAPI under your user profile. Never paste them into this conversation. This binds configuration to your Windows user/computer; keep your recovery key separately.
3. The scheduled task runs daily at 03:00 **in the computer's timezone**, with a hidden window and limited current-user privileges. Your user must be signed in and the machine available. It is not a continuously running hosted backup service. `-ConfigureOnly` saves configuration without scheduling. No task or private configuration has been created by the assistant.
4. Run `powershell -NoProfile -File scripts/run_private_backup.ps1` privately for the first backup and check that both creation and verification succeed. Default files live in `%LOCALAPPDATA%\GameArena\Backups`; inspect task history and verify dates/sizes regularly. No offsite destination or deletion/retention schedule is configured yet. A lost computer can lose all local copies, so choose independent encrypted storage before relying on this for production recovery.
5. Perform restore drills periodically. Set `GAMEARENA_BACKUP_KEY`, `GAMEARENA_RESTORE_DATABASE_URL` and optionally `GAMEARENA_PG_BIN` privately; create an **empty isolated** database named `gamearena_restore_...`. Run `python scripts/backup_database.py restore PATH.gabk --confirm-empty-database EXACT_DATABASE_NAME`. It refuses the original database, mismatched names, nonempty targets and targets with other sessions. Check actual records and financial ledger consistency afterward. These guardrails deliberately do not support overwriting production automatically. A synthetic local restore drill is not evidence that a production backup already exists.

## Dependency and secret checks

Weekly Dependabot updates and a GitHub Actions workflow run Python dependency auditing, frontend auditing and a fully redacted committed-history secret scan. They become active after the workflow is pushed to GitHub with Actions enabled; local configuration is not evidence of a completed remote run. Existing CI executes PostgreSQL-backed authorization/wallet tests. The strict script CSP now uses per-response nonces instead of `unsafe-inline`; existing inline style support remains.

Local Python audit resolved 53 packages with no known advisories on 19 October 2026. The frontend scan flags [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) in development-only `braces` 3.0.3, reached through Tailwind's tooling. The advisory lists no patched release. Do not process untrusted patterns in build tools or run a development server publicly. Production Render serves prebuilt CSS and Python and does not install this npm development dependency. The workflow intentionally still fails on the high advisory until it can be fixed; it is not silently suppressed. Replacing the styling toolchain needs separate compatibility testing. The history scanner likewise flags the old credential candidates until responsibly resolved; do not hide findings merely to make CI green.

The moderate [selector-parser advisory](https://github.com/advisories/GHSA-rj75-hqrm-r3gf) was addressed by a workspace override to `postcss-selector-parser` 7.1.6. A frozen install, TypeScript/Vite production build and standalone Tailwind CSS compilation passed with that override; the final frontend audit reports only the unpatched `braces` finding.

Passing tests or a clean advisory scan does not prove the application has no vulnerabilities. Continue scoped reviews when authentication, payments, permissions and infrastructure change.
